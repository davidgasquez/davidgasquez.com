The triple palindrome search

Is there a number above 9 that reads the same backwards in decimal, binary, and hexadecimal?

I got nerd-sniped by an episode of The Rest Is Science, Is 100 Better Than 101?. They talk about numbers that are palindromes in decimal, binary, and hexadecimal at once, noting that we don't know any non-trivial one.

Rick Regan asked this question back in 2010 in a short blog post, In search of decimal/binary/hexadecimal palindromes. He wrote some code and checked candidates up to 32 hex digits. He found no example longer than one digit! I wanted to see how far I could get in this day and age, when AI can do math better than I ever could.

My first instinct was that it should be easy, since I quickly found many near misses, like 585 and 153.

None of them pass all three, though. I had a couple of chats with an agent and came up with a heuristic good enough to push the search further.

The search heuristic

Each base has a mirror rule. In a palindrome, the first digit matches the last, the second matches the second to last, and so on. I start with the binary and hex mirror rules. The program ties together the bits that have to match, so it only builds candidates that pass both. These two rules alone narrow things a lot. For example, Regan showed in the structure of binary/hexadecimal palindromes that a number that is a palindrome in both binary and hex and starts with hex 9 can only use the digits 0, 6, 9, and F.

As the program fills in the bits, it uses the decimal mirror to rule out whole groups of candidates at once. If every number in a group starts with the same decimal digits, a decimal palindrome must end with those digits reversed. That decimal ending fixes the last few binary bits. The binary mirror has already fixed those same bits by copying the top bits in reverse. When the two disagree, no number in the group can work, so the search skips the whole group.

Why does a decimal ending fix binary bits? The last two bits of a number give its remainder when divided by 4. Any multiple of 100 divides evenly by 4, so only the last two decimal digits affect that remainder. Take 11, 111, and 211. They all leave a remainder of 3, and 3 in binary is 11, so all three end in the bits 11. In the same way, the last decimal digit fixes the last bit, which says whether the number is odd or even.

The figure below shows this on 14-bit numbers, using only the binary mirror. The top five bits are fixed and the bottom five mirror them. Since the four middle bits must also read the same backwards, each group holds only four numbers.

When the decimal ending and the binary mirror agree, the search keeps the group and checks it more closely. The program the agent wrote applies this check each time it fills in more bits. It also splits the work for each bit length, meaning each count of binary digits, into thousands of tasks that can run independently across machines or CPUs.

Results

I came back after a few hours and...

No number with 9 < N < 2448 is a palindrome in decimal, binary, and hex.

That covers every number above 9 with up to 112 hex digits, up to about 7.27 × 10134.

So, if you want to pick this up, the next range to search starts at 2448. Good luck!
